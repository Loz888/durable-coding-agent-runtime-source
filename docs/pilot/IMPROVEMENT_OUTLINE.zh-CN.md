- 对齐当前本地实现、公开基线、文档和进度；记录最终源码清单与版本，保留历史评测及失败日志。

- 最终执行完整回归、race、重复关键恢复测试和 vet；退出条件是最终快照的失败全部解决或明确阻塞，不能引用较早快照冒充最新全绿。

## P0：完成安全执行边界

- 复用现有沙箱 Executor 和独立候选快照；在可用容器引擎上验证无网络、只读、权限、CPU/内存/PID、超时、输出及取消清理。
- 验证 Worker SIGKILL 后孤儿资源的识别和回收，保持试点任务无法被可信本机 Worker 领取，禁止宿主执行兜底。
- 将完整候选树、依赖/测试配置与验证结果绑定；任何相关文件变化必须使缓存测试结论失效。
- 退出条件：真实正向与负向隔离测试通过后，才允许接收对应信任范围的仓库。

## P1：验证真实修复价值

- 复用现有 repair20 单文件边界、独立测试、严格评分和费用许可账本，建立覆盖不同失败原因的小规模任务集。
- 分别报告新修复、恢复复用、修复失败、越界拒绝、费用未知与不支持场景；模型输出、测试通过和业务修复正确分开判断。
- 已授权本轮上限 2 美元，仅合成缺陷仓库；先补安全验收，再在剩余额度内小批调用，不因重跑重置预算。

## P1：收口服务治理与恢复

- 扩充身份撤销、跨主体访问、幂等冲突、取消/完成竞争、限流和旧 Epoch 提交等现有 API 测试。
- 校验模型许可与未知费用保留在重启、超时、429 和供应商异常下的行为；保留独立的领取、重试、修复及 HTTP 计数。
- 建立运行、事件、补丁和 Worktree 的保留与清理规则，保证活跃运行不被误清理。

## P2：性能、运维与维护成本

- 补齐 Worker 吞吐、队列等待、数据库锁竞争、恢复耗时及持续运行实验；记录环境、分母和源码版本。
- 实际演练数据库恢复、权限恢复、优雅退出、重启和告警投递；多主机 Worktree 恢复仍需独立设计验证。
- 先补模块导航和稳定接口说明，再渐进整理 day 编号模块，避免为了改名破坏现有恢复协议。

## P3：扩大能力范围

- 在单文件链路安全且可靠后，增加受控多文件补丁、变更清单、统一验证和恢复协议。
- 按明确需求增加多主机工作目录重建、PR 交付或 CI 集成，不直接承诺任意大型仓库自主开发。

## 执行顺序
