# 测试策略

[English](../testing.md) | [简体中文](testing.md) | [中文首页](../../README.zh-CN.md)

本文介绍本仓库实现中的测试与验收标准。
可执行配置与测试命令见[中文 README](../../README.zh-CN.md)和[英文测试说明](../testing.md)。

## 环境与隔离

已记录的实现验证使用 Linux/WSL、Go 1.27.1 和 PostgreSQL 16。
数据库场景使用两个专用测试数据库。
夹具管理自己的数据行与随机补丁 schema，不使用生产任务数据库。

共享队列的独立夹具通过 PostgreSQL advisory lock 串行协调设置流程。
夹具内部的持有者续约与补丁行锁竞争仍以真实并发方式发生。

## 必须覆盖的场景

| 范围 | 验收条件 |
| --- | --- |
| 真实领取 | 接管通过实际队列领取操作取得任务 |
| 四种补丁状态 | SIGKILL 恢复覆盖 prepared、applied、verified_pass、verified_fail |
| 最终检查点窗口 | 补丁已验证，但 Agent 检查点之前崩溃，仍可恢复 |
| Worker 隔离校验 | 旧 Epoch 无法提交新持有者的结果 |
| Worktree 身份 | 丢失、被替换、被 rebase 或绑定不正确的工作区拒绝继续执行 |
| 修复预算 | 接管保留已有逻辑修复轮次预算 |
| 心跳竞争 | 续约与补丁行锁之间发生真实并发竞争 |
| 源码隔离 | 修改只发生在受管理的 Worktree 中 |
| 验证缓存 | 复用已保存的验证结果，无需再次调用模型 |
| 终态保护 | 已完成的 Run 不可再次领取 |

测试只终止夹具自己创建的子进程。
夹具仅推进自身 Run 的租约到期时间以控制等待时长；
下一次 Epoch 仍来自实际队列领取。

## 验收规则

实现工程的验收拒绝失败测试、跳过测试、缺失的必需场景和空结果。
数据库连接配置由调用方明确提供。
没有测试文件的包与被跳过的测试用例分别处理。

全项目测试分别以普通模式和 Go race detector 模式运行；
还检查不依赖数据库的测试集、重复修复测试、静态分析与构建。
详见[验证结果](validation.md)。

## 模型与夹具

Mock 修复使用确定性提案处理受控的 Divide 缺陷。
HTTP 模型适配器测试使用本地 HTTP 测试服务。
这些结果不能作为真实模型质量评估；验证期间未注入真实模型 API Key。

四个有意失败的嵌套 Go 模块作为诊断输入，另一个模块作为通过对照。
这些故意保留的失败没有被删除来制造成功结果。

## 编译缓存处理

race CI 在完整竞态测试之前，先编译普通测试依赖。
嵌套的普通 Go 测试进程与启用竞态检测的进程使用不同的标准库缓存。
预热普通缓存，避免冷启动编译消耗夹具严格限制的执行时间。

此准备步骤不替代任何验收场景。
执行时限、租约校验与所有测试断言均保持不变。

## Day21 输出隔离与验收

day21_accept.sh 检查全部 12 个 Capture 子场景，
重算已提交的 summary/report，并独立评分本次采集的数据。
普通测试、Mock/崩溃 Demo 和单元测试脚本会清除 DAY21_RUNS_OUT，
避免将重复观测追加到另一轮采集文件。
采集脚本仅为那一次 Capture 命令设置此变量。

普通、竞态与覆盖率验收使用 360 秒超时；
核心模块十轮回归使用 900 秒。调整超时不删除任何测试或断言。
运行方法及数据解释见[评测文档](evaluation.md)。

## 试点集成测试角色

新增 pilot API 夹具创建独立受限登录角色，并使用仅测试有效的随机密码，兼容 TCP/SCRAM。夹具管理连接需要创建/管理测试角色及在专用测试库授权的权限，建议使用独立测试集群或仓库 CI；不能通过提升正式 API 角色权限来运行测试。API 本身拒绝超级用户和所有者凭据。
